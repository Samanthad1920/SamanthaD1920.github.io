I’m a computer engineering graduate with interests spanning software development, embedded technology, and systems integration.

In my current role as an AI Integration IT Specialist in manufacturing IT, I work with internal applications and the technology that supports operational workflows. My work brings together frontend and backend development, databases, APIs, containerized environments, and troubleshooting across application and server layers.

I enjoy the process of understanding an existing system, identifying how its components interact, and determining the best way to extend or improve it. This often means working through unfamiliar code, tracing data between systems, resolving compatibility issues, and documenting the resulting solution.

My computer engineering background also shapes how I approach software. I am interested not only in making an application work, but in understanding the underlying systems, interfaces, and constraints that determine how it behaves.

Beyond my professional work, I explore technical systems design, personal knowledge-management workflows, and home technology infrastructure. These projects give me opportunities to practice requirements analysis, compare design trade-offs, and organize complex information into systems that are easier to maintain.

I am continuing to develop my skills with the goal of working on increasingly challenging engineering problems, particularly where software, hardware, and real-world systems meet.

## How I approach problems

**Understand before changing.** I investigate the existing behavior, dependencies, and constraints before deciding how to proceed.

**Follow the whole system.** I trace issues through the relevant layers, from the user interface to the application logic, data, APIs, and runtime environment.

**Make trade-offs explicit.** I consider compatibility, reliability, maintainability, cost, and complexity when comparing solutions.

**Document for the next person.** I aim to leave behind clear explanations, reproducible steps, and useful technical references.

## Project 4: Personal Knowledge and Project Management System

**Type:** Personal systems-design project
**Status:** Design and development of the workflow

### Overview

Designing a personal information system that separates active work, reference material, learning notes, and technical documentation while allowing information to remain connected across topics.

The goal is to create a system that makes information easier to capture, organize, retrieve, and use without forcing every type of information into one tool.

### Design decisions

* Use a project and task-management workspace for active work, milestones, decisions, and follow-up actions.
* Use a notebook system for learning notes, meeting notes, and general reference material.
* Keep source-code documentation and implementation-specific technical records close to the relevant repositories.
* Organize subject areas hierarchically while allowing topics to relate to multiple parent topics.
* Define workflows for deciding whether new information should remain a reference note or become a task, project, decision, or technical document.

### Engineering challenge

A useful information system must balance structure with flexibility. Excessively rigid categorization makes information difficult to organize, while an unstructured collection of notes makes it difficult to retrieve and apply.

### What this project demonstrates

* Requirements analysis
* Information architecture
* Workflow design
* Data relationships and classification
* Technical documentation strategy
* Tool selection and trade-off analysis

**Tools:** Notion, OneNote, GitHub

## Project 5: Home Lab and Network Infrastructure Planning

**Type:** Personal technical project
**Status:** Planning and hardware evaluation

### Overview

Planning a home technology environment that connects networking equipment, computers, local storage, and surveillance devices into a maintainable system.

The work includes documenting device capabilities, determining connection requirements, evaluating network topology, and considering local storage and video-retention needs.

### Areas of investigation

* Network architecture across the router, mesh Wi-Fi, wired Ethernet, and managed switching.
* NAS and NVR capabilities for local storage and camera recording.
* Hardware compatibility, drive support, connection ports, and bandwidth requirements.
* Storage-capacity and video-retention trade-offs.
* Cable selection and device-to-device connectivity.
* Cost, upgrade options, and future expansion.

### Engineering challenge

The individual devices must work together as a complete system. A suitable component in isolation is not necessarily the best choice when compatibility, network limitations, storage requirements, and future expansion are considered together.

### What this project demonstrates

* Systems architecture and integration planning
* Hardware and specification analysis
* Network design fundamentals
* Storage and capacity planning
* Technical documentation
* Evaluation of cost and design trade-offs

**Areas:** Networking, NAS, NVR, Ethernet, storage, hardware/software integration
